# 健身動作評分：專題規劃

## 已確定的方向（2026-10-17）

| 項目 | 決定 |
|---|---|
| 平台 | **手機網頁**：用手機瀏覽器開啟，直接用手機鏡頭拍攝 |
| 動作 | **深蹲**、**伏地挺身** |
| 評分方法 | **關節角度規則**（指出哪裡錯）＋ **DTW 比對標準動作**（整體像不像） |
| 帳號與紀錄 | **加入**：辨識與評分在手機上做，輕量後端只存帳號、紀錄與實驗資料（不存影像） |

## 1. 系統架構

```
手機鏡頭（getUserMedia）→ MediaPipe Pose Landmarker（瀏覽器內推論）
  → 前處理（平滑、可見度過濾）
  → 計次與切分（每一下的起訖）
  → 特徵：關節角度序列
  → 評分：規則扣分 + DTW 相似度 → 綜合分數 + 文字/語音回饋
  → 每組結束後：把分數、次數、角度序列上傳到後端（帳號、紀錄）
```

辨識與評分全部在手機瀏覽器內執行，所以即時回饋不受網路影響；影像不會上傳，只上傳數字，隱私上也比較好說明。後端只負責帳號與資料保存，斷網時先存在手機，連線後再同步。

## 2. 技術選型

| 部分 | 選擇 | 原因 |
|---|---|---|
| 姿態估計 | **MediaPipe Tasks Vision（JS 版 Pose Landmarker）** | 33 個關節點（含腳跟、腳尖），可用 GPU 加速，手機瀏覽器跑得動 |
| 前端 | 純 HTML/JS 或 Vite + React | 原型用純 JS 最快，之後再視需要換框架 |
| 畫面 | `<video>` + `<canvas>` 疊加骨架 | 即時顯示關節點與角度 |
| 回饋 | 畫面文字＋ Web Speech API 語音提示 | 做動作時看不到螢幕，語音比較實用 |
| 帳號 | **Firebase Authentication**（Email / Google 登入） | 免寫登入系統，免費額度足夠專題使用 |
| 資料庫 | **Cloud Firestore**；離線時暫存在 IndexedDB | 前端直接讀寫、內建離線同步，不用自己架伺服器 |
| 部署 | GitHub Pages、Netlify 或 Vercel | **鏡頭必須在 HTTPS 下才能開啟**，這些平台都免費提供 HTTPS |
| 分析與調參 | Python（NumPy、pandas、matplotlib） | 匯出角度資料做離線分析、畫圖放報告 |

模型選擇：先用 `pose_landmarker_lite`，較舊的手機若太慢再降低解析度；新手機可試 `full` 提高精度。

## 3. 拍攝方式（要寫進使用說明）

- **側面拍攝**：手機橫放或直放在地上/靠牆，鏡頭與身體側面垂直，全身入鏡。深蹲與伏地挺身的主要判斷（膝角、肘角、身體直線）都靠側面最準。
- 開始前做「校正」：站定 1–2 秒，確認全身關節點可見度足夠才開始計次。
- 自動判斷面向左側或右側，使用較靠近鏡頭那一側的關節點。
- 限制：側面看不到膝蓋內夾，報告中列為限制，或作為未來加入正面視角的延伸。

## 4. 評分方法一：關節角度規則

角度用三個關節點計算，例如膝角＝髖–膝–踝的夾角。

### 深蹲

| 檢查項目 | 計算方式 | 參考門檻（需實測調整） | 回饋 |
|---|---|---|---|
| 蹲的深度 | 最低點膝角 | ≤ 90° 滿分，> 110° 視為過淺 | 「再蹲低一點」 |
| 軀幹前傾 | 肩–髖連線與垂直線夾角 | ≤ 45° | 「胸口挺起來」 |
| 腳跟離地 | 腳跟與腳尖的高度差變化 | 變化小於門檻 | 「重心放腳跟」 |
| 完整站起 | 最高點髖角與膝角 | ≥ 165° | 「站直再蹲下一下」 |
| 節奏 | 下蹲時間 | 不要過快（例如 < 0.8 秒） | 「慢一點控制」 |

### 伏地挺身

| 檢查項目 | 計算方式 | 參考門檻（需實測調整） | 回饋 |
|---|---|---|---|
| 下降深度 | 最低點肘角 | ≤ 90° | 「再往下一點」 |
| 身體直線 | 肩–髖–踝夾角（整個過程） | 160°–190°；過小是翹臀，過大是塌腰 | 「核心收緊，不要塌腰」 |
| 完整推起 | 最高點肘角 | ≥ 160° | 「手臂打直」 |
| 頭頸位置 | 耳–肩–髖夾角 | 不過度抬頭或低頭 | 「眼睛看地板前方」 |

### 計分
每一下：`規則分 = 100 − Σ(權重 × 偏離程度)`，偏離程度依超出門檻的角度線性換算，上限為該項權重。每項錯誤同時對應一句回饋，一組做完後顯示最常出現的錯誤。

### 計次（狀態機）
- 深蹲看膝角，伏地挺身看肘角。
- 角度低於「下門檻」記為「下」，回到「上門檻」記為「上」，完成一上一下算一次。
- 兩個門檻之間留緩衝區（遲滯），避免抖動造成重複計次。

## 5. 評分方法二：DTW 比對

1. **建立標準模板**：請動作標準的人（教練或有訓練經驗的同學）用同樣的拍攝方式錄 5–10 下，切成單次，存下每一下的角度序列。
2. **特徵向量**：每個時間點取多個角度，例如深蹲用 [膝角, 髖角, 軀幹前傾]，伏地挺身用 [肘角, 肩–髖–踝角, 肩角]。
3. **正規化**：角度本身就與身高、距離無關；序列可再做 z-score 或除以 180°。
4. **比對**：使用者每一下與每個模板做 DTW，取最小距離（或平均）；加上 Sakoe-Chiba 窗口限制可加速並避免不合理的對齊。
5. **換算分數**：例如 `DTW 分 = 100 × exp(−距離 / k)`，k 由收集到的資料決定（讓標準動作約 90 分、明顯錯誤約 50 分）。
6. **綜合分數**：`總分 = α × 規則分 + (1 − α) × DTW 分`，α 先設 0.6，再用人工評分資料調整。

DTW 在瀏覽器用 JS 自己實作即可，每一下只有數十個時間點，計算量很小。

## 6. 帳號與紀錄功能

### 功能
| 功能 | 說明 | 優先 |
|---|---|---|
| 註冊 / 登入 | Email 或 Google 帳號 | 必做 |
| 訓練紀錄 | 每組的動作、日期、次數、平均分、各項錯誤次數 | 必做 |
| 單次細節 | 每一下的分數、扣分項目，可展開角度曲線圖 | 必做 |
| 進步趨勢 | 以週/月為單位畫平均分數與次數折線圖 | 建議 |
| 個人標準模板 | 使用者或教練錄製自己的 DTW 模板，存在帳號下 | 建議 |
| 實驗模式 | 標記受試者編號，資料可匯出 CSV 給 Python 分析 | 建議（做實驗時很省事） |
| 教練 / 管理者 | 查看指定學員的紀錄 | 加分 |

### 資料結構（Firestore）
```
users/{uid}
  name, createdAt, height(選填)
  sessions/{sessionId}
    exercise: "squat" | "pushup"
    startedAt, reps, avgScore, ruleScore, dtwScore
    errorCounts: { depth: 2, backSag: 1, ... }
    device: { model, fps }
    reps/{repIndex}
      score, ruleScore, dtwScore, errors: [...]
      angles: { knee: [...], hip: [...], ... }   ← 角度序列（數字，不存影像）
templates/{templateId}
  exercise, ownerUid, createdAt, reps: [角度序列...]
```

### 安全規則
- Firestore Security Rules 限制每個人只能讀寫自己的 `users/{uid}`。
- 公用模板只有管理者能寫入，所有人可讀。
- 實驗資料用受試者編號、不存真實姓名，報告中說明有取得受試者同意。

### 替代方案
若老師要求自己寫後端，可改用 **Python FastAPI + SQLite/PostgreSQL**，用 JWT 做登入，部署到 Render 或 Railway。資料結構相同，只是多了寫 API 與部署的工作，大約多出一個階段的工作量。

## 7. 驗證（報告的實驗章節）

- 找 5–10 位受試者，每人每個動作錄「正確」與「刻意錯誤」（蹲不夠深、塌腰等）各數下。
- 請有訓練背景的人對每一下人工打分。
- 計算系統分數與人工分數的相關係數（Pearson / Spearman），並比較「只用規則」、「只用 DTW」、「兩者結合」三種方式。
- 計次準確率：系統次數 vs 實際次數。
- 記錄不同手機的畫面更新率（FPS），說明效能。

公開資料集可當補充（例如 Fitness-AQA、EC3D 有深蹲錯誤標註），但使用前需確認授權與拍攝角度是否相符。

## 8. 路線

| 階段 | 內容 | 完成標準 |
|---|---|---|
| 1. 鏡頭與骨架 | 手機網頁開啟後鏡頭、MediaPipe 偵測、canvas 畫骨架、即時顯示角度；部署到 HTTPS | 手機上能看到骨架跟著動 |
| 2. 計次 | 深蹲與伏地挺身的狀態機計次 | 計次正確率 ≥ 95% |
| 3. 規則評分 | 依第 4 節做逐次扣分與文字/語音回饋 | 每一下都有分數與回饋 |
| 4. DTW | 模板錄製功能、DTW 比對、綜合分數 | 標準與錯誤動作分數有明顯差距 |
| 5. 帳號與紀錄 | Firebase 登入、上傳每組紀錄、歷史列表、實驗模式與 CSV 匯出 | 換手機登入也看得到紀錄 |
| 6. 資料收集與調參 | 第 7 節的實驗，調整門檻、k、α | 有相關係數與比較表 |
| 7. 介面完善 | 結果頁、進步趨勢圖、使用說明 | 可給別人實際使用 |
| 8. 報告與展示 | 整理架構、實驗結果、限制 | 書面報告、簡報、現場 demo |

## 9. 風險與對策

| 風險 | 對策 |
|---|---|
| 舊手機 FPS 太低 | 用 lite 模型、降低輸入解析度、每隔一幀推論 |
| 伏地挺身時人貼近地面，關節點容易抖或遺失 | 手機放低、側面拍；可見度低的幀不列入評分；加平滑濾波 |
| iOS Safari 鏡頭與自動播放限制 | 需使用者點按鈕才開鏡頭；`<video>` 加 `playsinline muted` |
| 門檻因人而異 | 用實驗資料調整，並在報告中說明 |
